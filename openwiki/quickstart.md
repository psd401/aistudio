# AI Studio

**Bring frontier AI to K-12 education—securely, affordably, and responsibly.**

AI Studio is an open-source platform that provides K-12 educators and students with access to cutting-edge generative AI models. Built with privacy-first architecture and deployed within district infrastructure, it offers multi-model access (GPT-5, Claude Opus, Gemini) at a fraction of individual subscription costs.

## What This Codebase Does

| Domain | Description |
|--------|-------------|
| **Nexus Chat** | Conversational AI with automatic model routing (including PSD-data queries), conversation history, MCP tool integration, and real-time streaming |
| **Assistant Architect** | No-code custom AI assistant builder with visual prompt chain designer, variable substitution, and scheduled execution |
| **Atrium** | Agent-native content workspace supporting documents and interactive artifacts with viewer-scoped data bridge, drag-and-drop organization, and permission-aware publishing |
| **Agent Platform** | Extensible skill system for AI agents with Google Workspace integration, Cedar-based governance, and MCP tool exposure |
| **Knowledge Repositories** | Document upload, OCR processing, vector embeddings, and semantic search for context-aware AI responses |
| **API Platform** | REST API v1 for external integrations, OAuth2/OIDC provider, and API key management |

## Critical Development Rules

1. **Type Safety**: No `any` types. Run `bun run lint` and `bun run typecheck` before commits
2. **Database Migrations**: Files 001-005 are immutable. Add migrations 010+ and update `/infra/database/migrations.json`
3. **Logging**: Never use `console.log/error`. Use `@/lib/logger` (exception: standalone CJS scripts)
4. **Git Flow**: PRs target `dev` branch, never `main`
5. **SSE Keep-Alive**: Long-running AI turns require SSE comment frames (`: keep-alive\n\n`) every 15s to prevent ALB idle timeout. Use `withSseKeepAlive` for existing streams or `deferUIMessageStreamResponse` for deferred responses. SEE **[architecture/streaming.md](architecture/streaming.md)** for complete contract (#1698).
6. **Nexus Conversations**: Read `/docs/features/nexus-conversation-architecture.md` before modifying conversation code — repository bindings, readiness gates, and tool scoping have subtle invariants
7. **Attachment Adapters**: When modifying attachment code, the conversation ID accessor must be closure-backed, never a memo dependency of the adapter — see **[app-features/overview.md](app-features/overview.md#attachments-1735)** for shared hook pattern (#1735)
8. **Workspace Artifact Routing**: An editable artifact open beside chat gets PSD Data connector attached regardless of message classification — "add a dropdown" on a live dashboard is a schema question. See **[app-features/overview.md](app-features/overview.md#workspace-artifact-psd-data-routing-1786)** for routing predicates and do-not-guess guidance (#1786)
9. **Repository Readiness**: Empty repositories bind but don\'t block chat turns; `searchableRepositoryIds` excludes them from tool scope — see **[app-features/overview.md](app-features/overview.md#repository-readiness-gate)** for the gate contract (#1733)
10. **API Changes**: Update both `docs/API/v1/openapi.yaml` and `docs/API/v1/context-graph.md` for API v1 modifications
11. **Visibility Changes**: Read grants before modifying — `PATCH /content/:id/visibility` replaces the grant list, use `--add-grants`/`--remove-grants` for merge operations (#1763)
12. **Grant Targets**: `user` and `group` grants validate target existence before storing; see **[app-features/overview.md](app-features/overview.md#grant-target-existence-validation-1777)** for contract (#1777)
13. **Typed Bridge Errors**: AtriumData bridge failures carry typed `err.code` (unauthenticated, forbidden, not_query_mode, rate_limited, timeout, query_error, too_many_requests, unavailable). Wrap every bridge call in try/catch — see **[app-features/overview.md](app-features/overview.md#typed-bridge-errors-1787)** for contract and handling pattern (#1787)
14. **Artifact Data Concurrency** (#1788): Queries now run in parallel (up to 6 at once) via fetch Route Handler, not serialized Server Actions. Excess requests queue rather than reject. The server's 30s budget spans preflight + MCP handshake + execution — see **[app-features/overview.md](app-features/overview.md#query-concurrency-and-transport-1788)** for concurrency, timeout, and queue contracts.
15. **MCP Tool Versioning**: Tool schemas are immutable at a given version — changing a schema requires bumping the version. Old versions must be preserved as frozen legacy entries in `LEGACY_MCP_MANIFEST_ENTRIES`. See **[api-integration/overview.md](api-integration/overview.md#mcp-tool-versioning-contract)** for versioning contract (#1710, #1817)
16. **Toast & Form Validation**: The app uses sonner for toasts; `useToast()` is an adapter — never mount a second toast root. For blocked form submits, use `handleSubmit` callbacks (not `trigger()` + `formState.errors`) and ensure fields forward refs for `setFocus`. `useFormField` must use `useFormState({ name })` to subscribe. See `/docs/guides/silent-failure-patterns.md` and **[app-features/overview.md](app-features/overview.md#create-form-validation-1697)** for patterns (#1697)
17. **Drive Query Parameters (#1801)**: `--params` MUST be a parseable JSON object. Single-quoted values (Drive `q` parameter) cannot survive tokenizer — use `--params-file` instead. The broker rejects unparseable `--params` with reason `params_not_json` before any mutation gates run. See **[agent-platform/overview.md](agent-platform/overview.md#query-parameter-validation-security-1801)** for order invariant and payload-file flow changes.
18. **Web Fetch Tool (#1696)**: Nexus chat attaches `web_fetch` on every turn (NOT single-step surfaces like model compare). Page text is fenced as `<untrusted_web_content>` — the model must never follow directions inside the fence. Skill `allowed-tools` pins can exclude it. A URL message routes as `general`, never as `web-search`, so the turn never fails for lack of a search-capable model. See **[app-features/overview.md](app-features/overview.md#web-fetch-tool-1696)** for SSRF guards, content fencing, routing implications, and step budget.
19. **Artifact Preview Frame** (#1788): The canvas keeps the preview iframe mounted on tab toggle to avoid re-running queries. A frame is kept hidden, never first created hidden — charting libraries would initialize at zero size. See **[app-features/overview.md](app-features/overview.md#query-concurrency-and-transport-1788)** for mount key contract.
20. **Workspace Object Binding** (#1791): Conversations opened beside an Atrium artifact record `workspace_object_id` durably — reopening from sidebar restores the panel; "Ask the agent" continues the bound conversation instead of starting fresh. See **[app-features/overview.md](app-features/overview.md#workspace-object-binding-1791)** for binding operations and restore flow.
21. **Draft Auto-Send Handshake** (#1791): In-app navigation to Nexus can auto-send a prefilled draft via a same-tab sessionStorage handshake (`armDraftAutoSend` + `consumeDraftAutoSend`). Links from outside the app only prefills — cannot trigger auto-send. See **[app-features/overview.md](app-features/overview.md#draft-auto-send-handshake-1791)** for security model.
22. **Rename/Re-slug** (#1791): Workspace chat can rename content via `rename_workspace_content` tool. An unpublished rename allocates a fresh slug; ever-published keeps the original slug. See **[app-features/overview.md](app-features/overview.md#rename-and-re-slug-1791)** for transaction and collision handling.
23. **Mode-Only Artifact Updates** (#1791): `update_workspace_artifact` can change only `dataAccess` without providing `code` — no version is created, no §28.3 screening runs. See **[app-features/overview.md](app-features/overview.md#mode-only-artifact-updates-1791)** for contract.
24. **Version Authorship Labels** (#1791): Versions written by Nexus chat show "via Nexus chat" in the dropdown and About rail. The label is viewer-neutral — never "you". See **[app-features/overview.md](app-features/overview.md#version-authorship-labels-1791)** for labeling rules.
25. **Version-Scoped Data-Access Mode** (#1789): `data_access` lives on `content_versions`, not just `content_objects`. Live pages pin the PUBLISHED version's mode — author draft changes cannot re-capability Live. Use `resolveVersionDataAccess()` for every mode resolution. See **[app-features/overview.md](app-features/overview.md#version-scoped-data-access-mode-1789)** for the complete contract.
26. **Artifact Query Limits** (#1792): Numeric limits are defined in ONE module (`lib/content/artifact-query-limits.ts`) and interpolated into model-facing guidance. Default limit is 200 — an unaggregated query silently returns first 200 rows. When changing limits, update both the constant AND the skill file (`infra/agent-image/skills/psd-atrium/SKILL.md`). See **[app-features/overview.md](app-features/overview.md#shared-data-contract-1749-1792)** for limit table and synchronization requirements.
27. **Workspace Panel Resizing** (#1793): Panel width is user-controlled and persists as fraction in localStorage. Minimum widths (380px panel, 320px chat) are enforced; panel wins on narrow containers. Full-screen viewport always shows back control. See **[app-features/overview.md](app-features/overview.md#workspace-panel-layout-1793)** for persistence, clamping, and keyboard accessibility.
28. **Authenticated Embeds Data Bridge** (#1790): `ArtifactEmbedBlock` in authenticated readers (`/c/`, editor NodeView) gets the data bridge for LIVE artifacts — `resolveEmbedForReader` decides by audience, not the reader component. Public reader (`/p/`) always resolves `dataBridge: null`. Unpublished artifact embeds render head with NO bridge. See **[app-features/overview.md](app-features/overview.md#live-data-artifact-sharing-1790)** for bridge table and fail-closed contract.
29. **Grant Passage** (#1837): An item explicitly shared with a user or group is visible even when its containing collection restricts them — `group`-level objects with matching grants, and `private` objects with per-user grants, reach their grantees through active district collections that would otherwise deny entry. The sidebar lists only shared items in passage collections; internal/public siblings stay hidden. See **[app-features/overview.md](app-features/overview.md#grant-passage-1837)** for the complete contract.
30. **Live Follows Save** (#1837): A save to a Live object advances its publication to the new version without requiring Republish — readers of `/c/{slug}` always see the latest saved version. Live stays pinned (`published_version_id` unchanged) only when the collection requires approval, or when the new version's data-bridge mode differs from the Live version's. See **[app-features/overview.md](app-features/overview.md#live-follows-save-1837)** for exceptions and migration 185 backfill.
31. **Workspace Artifact Tier Floor** (#1840): While an editable artifact is bound to a Nexus turn, the router raises the tier floor from `light` to `medium` — short follow-ups ("did that work?") need tool-calling models. The floor is a minimum, not a cap; a high classification keeps its tier. Shadow mode with required tools withholds the floor to avoid rerouting live traffic. See **[app-features/overview.md](app-features/overview.md#workspace-artifact-tier-floor-1840)** for predicate scope, shadow interaction, and reason codes.
32. **Preview Failure Delivery** (#1839): Artifact preview failures reach the model on every turn, not only via `read_workspace_content`. The failures arrive in a PREVIEW FAILURES block appended LAST to the system prompt, carrying only server-controlled values (count, kind, code). The block survives skill pins and models without function calling. Image-generation and Deep Research turns return the diagnostics via `X-Preview-Diagnostics-Unconsumed` header for client restore. See **[app-features/overview.md](app-features/overview.md#preview-failure-delivery-1839)** for complete contract.
33. **Google Chat Message Budget** (#1845): Google Chat messages carry **32,000 bytes** of text plus cards, not 4,096 characters. The `chat-text-budget` module measures serialized request bytes (JSON escaping counts), reserves space for card payloads, and cuts grapheme-safe at the boundary. The transport truncates after the agent finishes, so the agent's transcript holds full text the user may not have received. When a user says "you cut that off", they are right — re-deliver the tail or publish to Atrium and share the link. The durable outbox is 240 KiB so retries never drop accepted replies. See **[infrastructure/overview.md](infrastructure/overview.md#chat-text-budget-1845)** for module contract and **[agent-platform/overview.md](agent-platform/overview.md#transport-truncation-awareness)** for agent guidance.
34. **Scheduled Run Silent Reply** (#1853): A scheduled run that ends with exactly `NO_REPLY` (the silent token) posts nothing to the owner's DM — no header, no fallback. Use this for watchers and monitors that should stay quiet when nothing changed. The token works only for scheduled runs (source: "scheduled"); interactive turns with NO_REPLY still fire the nudge. The harness preserves the token in the transcript; only the delivery path strips it. See **[agent-platform/overview.md](agent-platform/overview.md#scheduled-run-silent-reply-1853)** for token matching rules, harness contract, and historical context.
35. **Email Triage Content-First Classification** (#1855, #1861, #1866): The classifier runs three stages in order: user rules → content stage (sender-independent) → LLM. Same message from different addresses lands on the same label. Human senders (unproven-automated) are never muted or marked as news. Rhetorical questions ("Think this is awesome?") are not direct questions — a question clause must speak to the reader in second person (`hasDirectQuestion`). Automated/bulk senders are vetoed from the question/action-request branch; those fall through to LLM or default `later`. Approval requests are exempt. Newsletters, digests and list mailings with no ask are **News**, not Later (`bulkPublication`, #1866); a colleague's post to a district Google Group stays Later. Content-stage confidence is 0.7; high-confidence escalation requires `source === "llm"`. Keyword rules have stable `id` fields; malformed rules are deleted via `--malformed`. Corrections teach per-shape leanings (Later, News or Important) that demote or, for machine mail, move to News. Real digest counts come from `dailyStats` (45-day retention), not capped `recentDecisions`. See **[agent-platform/overview.md](agent-platform/overview.md#email-triage-content-first-classification-1855-1861)** for the complete pipeline, the runtime topology, human protection rules, and the skill mirror that must stay in parity.
36. **Atrium Per-Person Sharing** (#1860): A `user` grant stores a numeric `users.id`, never an email. Per-person sharing requires two steps: `find-people --query <email|name>` to resolve, then `set-visibility --add-grants user:<id>`. For staff who never signed in, `add-person --email <district-email>` creates the id. Only `@psd401.net` addresses accepted; student-number addresses and other domains are rejected. **Always verify the returned email** before granting — server cannot verify intended recipient. `users` is a sign-in-derived population, not a directory mirror — colleagues who never signed in have no row until created. See **[agent-platform/overview.md](agent-platform/overview.md#atrium-per-person-sharing-1860)** for the complete contract, query bounds, and user table derivation.
37. **Agent File Delivery** (#1885): An agent hands a generated file to its requester privately by default — created in the agent's own Drive account and shared with that one user as `writer`. `--to public` (unsigned, 30-day link) is the exception, for genuinely public content. Word, Excel and PowerPoint can go only to Drive. A `share_failed` must be retried, never converted to a public link; there is no public fallback on this path. See **[agent-platform/overview.md](agent-platform/overview.md#private-file-delivery-to-drive-1885)** for the staged-upload flow and type policy.
38. **Scheduled Post Threads** (#1891): A reply in the Chat thread of a delivered scheduled post resolves to that run's transcript through the `psd-agent-thread-sessions` table; all other threads keep the `space + thread` key. The mapping is best-effort and owner-checked, and its expiry is enforced by the reader because DynamoDB TTL is asynchronous. See **[agent-platform/overview.md](agent-platform/overview.md#scheduled-post-thread-mapping-1891)**.
39. **Gmail Draft Revision** (#1894): Agents revise a draft with `gmail +draft --draft-id <id>`, which replaces that draft in place. A plain `+draft` rerun creates a second draft, and `drafts delete` is forbidden, so stale drafts cannot be removed. The `+draft` helper is expanded by the broker after validation and refuses unknown flags, so attachments are not silently dropped. Threading requires `--thread-id` together with `--in-reply-to` and `--subject`. The agent footer is applied once. See **[agent-platform/overview.md](agent-platform/overview.md#gmail-draft-helper-draft-1894)** for the flag contract, invariants, and validation.
40. **Credential Entry (#1887)**: Agents never ask a user to paste a secret into chat. `psd-credentials/request_entry.js --name <slot>` mints a single-use, 15-minute link; the user types the value into `/agent-connect-credential`, and the server action writes it through `AgentCredentialBroker.put`. The claim happens before the write, so a failed write spends the link. `--value` is refused on purpose, and `/agent-connect-credential` must stay out of `PUBLIC_PATHS`. See **[agent-platform/credential-entry.md](agent-platform/credential-entry.md)** for the lifecycle, invariants, and tests.
41. **Agent Schedule Validators Are Duplicated** (#1888): Cron rules live twice — `lib/agent-schedules/validation.ts` (server) and `infra/agent-image/skills/psd-schedules/common.js` (skill). No automated sync exists; port every fix to both and run both suites. Schedule responses carry `description` and `nextRuns` read-back, and `nextRuns` is empty for disabled schedules. See **[agent-platform/agent-schedules.md](agent-platform/agent-schedules.md)** for the rules, the audit script, and the test matrix.
42. **Platform Cutoff Hint (#1897)**: When a turn is cut short by the platform, OpenClaw prepends a note to the next turn saying the previous run was aborted, which would make the model believe the user stopped it. The image build rewrites that note to name the platform cause (`SYSTEM_CUTOFF_HINT` in `infra/agent-image/openclaw_aborted_hint.mjs`), and psd-rules R15 must carry the same instructions. Change the constant and the rule together. See **[agent-platform/overview.md](agent-platform/overview.md#aborted-run-session-hint-1897)** for the patch, invariants, and tests.
43. **Scheduled Run Status Is Not Success** (#1890): A run whose Chat post is queued for retry is recorded `deferred`, and the router settles it later. `deferred` and `error` extend a failure streak; `skipped` and `promoted` decide nothing. `list` marks a schedule `failing` at 3 consecutive failures, and the owner gets one DM per streak, suppressed by the `owner_notified_at` stamp (migration 188). Change the status sets, the streak SQL, and the partial index together, then run the streak smoke test. See **[agent-platform/schedule-failure-notices.md](agent-platform/schedule-failure-notices.md)**.
44. **Schedule Create and Update Refuse Duplicates** (#1889): A create or update that would leave a second enabled schedule with the same cadence, timezone, and prompt returns 409 `possible_duplicate`. A taken name returns 409 `name_conflict`. Both carry the existing schedule id, and `confirmNew` skips only the duplicate check. The create and update responses report run health as zero, so call `list` to see `failing`. See **[agent-platform/agent-schedules.md](agent-platform/agent-schedules.md#duplicate-and-name-refusals-1889)**.
45. **Repository MCP Writes** (#1907): `repositories_create` and `repositories_add_item` need the OAuth or API scope and the caller's live `knowledge-repositories` capability, re-checked inside the handler. A scope alone never permits a write, and a new write scope also has to be allowed on the OpenClaw client (migration 189 pattern). Created repositories are private. An added item is never reported searchable on return: `searchable` is `"no"` or `"keyword"` depending on the write path. On the legacy path, confirm with `repositories_search` filtered to the item's `repositoryId` (an untargeted search covers only the first 50 repositories). See **[app-features/overview.md](app-features/overview.md#repository-mcp-tools-1266-1907)** for the contract and **[api-integration/overview.md](api-integration/overview.md#openclaw-client-scopes-migration-189)** for the client scope set.
46. **Answer-less Turns Are Explained** (#1899): A turn with reasoning, files, or tool calls but no written text must end with a notice, not a blank bubble, and the notice is persisted so it survives a reload. Anchor the check on a TEXT part, not on "some chunk arrived": the Nexus Thread registers no Reasoning or File renderer. A direct-render tool (`lib/tools/direct-render-tools.ts`) counts as the answer, so no notice follows it. Stream errors use `sanitizeStreamErrorMessage`, never the AI SDK default. See **[architecture/streaming.md](architecture/streaming.md#answer-less-turns-and-error-notices-1899)** for the classification rules and persistence branches.
